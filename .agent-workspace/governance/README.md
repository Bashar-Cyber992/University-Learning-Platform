# 🏛️ دليل تشغيل طبقة الحوكمة والرقابة (SECOD Governance Layer Manual)

مرحباً بك في دليل تشغيل **طبقة الحوكمة المستقلة لـ SECOD**. هذا الدليل موجه للمهندسين والمشرفين التقنيين لإدارة وتشغيل منظومة الرقابة، بوابات الجودة، ومحرك القرارات.

---

## 1. الفلسفة المعمارية الحاكمة

> **Orchestrator Executes — Supervisor Verifies & Governs**  
> المنسق يقود وينفذ — والمشرف يتحقق ويحكم ويعتمد.

في منظومة SECOD، تم فصل سلطة التنفيذ عن سلطة الاعتماد بصورة دستورية صارمة:
- لا يُسمح لمنسق المنظومة (`secod-orchestrator`) باعتماد أي مرحلة بذاته.
- لا يُسمح لأي وكيل تنفيذي باعتبار مهمته منتهية بمجرد إرسال بطاقة Handoff.
- التحقق المادي من الملفات على القرص هو الأساس الوحيد للاعتماد، ولا يُعتد بالملخصات النصية.

## 3. محرك الحوكمة البرمجي (`engine.py`)

لتجنب التخمين وضمان التنفيذ الحسابي الصارم للقرارات، تم بناء محرك برمجي بلغة Python 3 خالي من أي تبعيات خارجية (`Zero External Dependencies`):

### 📌 الأوامر الأساسية للمحرك:

1. **عرض الحالة الراهنة لسير العمل:**
   ```bash
   python3 .agent-workspace/governance/engine.py status
   ```

2. **فحص مخرجات بوابة جودة محددة:**
   ```bash
   python3 .agent-workspace/governance/engine.py verify-gate --gate GATE-01 --dir .agent-workspace/production/lecture-01
   ```

3. **إصدار أمر تصحيح وزيادة العداد:**
   ```bash
   python3 .agent-workspace/governance/engine.py request-revision --gate GATE-01 --agent academic-analyst --file 01-analysis/lecture-analysis.md --desc "إسقاط الشريحة رقم 5"
   ```

4. **اعتماد بوابة ونقل الحالة للمرحلة التالية:**
   ```bash
   python3 .agent-workspace/governance/engine.py approve-gate --gate GATE-01 --next-stage "Academic Research"
   ```

5. **تشغيل حزمة اختبارات المحاكاة السبعة:**
   ```bash
   python3 .agent-workspace/governance/engine.py run-tests
   ```

## 4. الإجراءات التشغيلية القياسية (SOP: Standard Operating Procedures)

### الخطوة 1: انطلاق إنتاج المحاضرة
- يقوم المنسق بتهيئة مجلد المحاضرة في `.agent-workspace/<Course>/<Lecture>/`.
- يقوم المشرف بتحديث `workflow-state.json` ببدء سير العمل وتفعيل `GATE-01`.

### الخطوة 2: استلام التسليم من المنسق
- يرسل المنسق إشعاراً للمشرف باكتمال مخرجات المرحلة.
- يقوم المشرف بتحويل حالة سير العمل إلى `UNDER_REVIEW`.

### الخطوة 3: الفحص الجنائي للأدلة
- يفحص المشرف الملفات على القرص باستخدام المحرك البرمجي.
- يتأكد من: الوجود، الحجم، الأسطر، خلو وسوم `[TODO]`، مطابقة الشرائح، والمعايير.

### الخطوة 4: إصدار القرار
- **إذا استوفت الشروط:** يصدر المشرف قرار `APPROVE`، ويوثق ذلك في `audit-log.md`، ويأمر المنسق ببدء المرحلة التالية.
- **إذا وُجدت عيوب:** يصدر المشرف `REQUEST_REVISION`، ويتم خصم محاولة من رصيد المحاولات (2 كحد أقصى).
- **إذا فشلت المحاولة الثانية:** تُجمد الحالة فوراً إلى `HUMAN_REVIEW` ويتم تصعيد الأمر للمستخدم.

---

## 5. ضوابط حماية الموقع الحي (Zero Regression Boundaries)

1. **العزل التام:** يُمنع إنشاء أو تعديل أي ملف في المجلدات الإنتاجية للموقع (`assets/`, `components/`, ومجلدات المقررات الحية) طوال دورة حياة الحوكمة والاختبار.
2. **إذن النشر البشري:** لا يتم نقل أي محاضرة من `.agent-workspace/` إلى الموقع الحي إلا بعد الحصول على توقيع وموافقة صريحة ومكتوبة من المستخدم البشري المالك للنظام.
