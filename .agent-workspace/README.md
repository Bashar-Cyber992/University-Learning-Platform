# 🏗️ SECOD Agent Workspace (`.agent-workspace`)

هذا المجلد هو **بيئة العمل التشغيلية الوسيطة** لمنظومة وكلاء الذكاء الاصطناعي في منصة **SECOD**. يُستخدم هذا المجلد لتنظيم وتوثيق خطوات معالجة المحاضرات الجامعية وتخزين المخرجات المرحلية والوثائق التحليلية من لحظة استلام المادة الخام وحتى اكتمال الجودة والاعتماد.

---

## 🚫 قواعد صارمة لإدارة مساحة العمل (Strict Workspace Rules)

1. **حظر نقل ملفات الموقع الأساسية:** **يُمنع منعاً باتاً** نقل أو نسخ أو استضافة ملفات الموقع الفعلية (مثل `index.html` أو `courses.html` أو ملفات مجلدات `assets/` و `components/`) داخل هذا المجلد.
2. **العزل التام للمخرجات المرحلية:** هذا المجلد مخصص حصراً للأصول الوسيطة (ملفات المصدر، وثائق التحليل، تقارير البحث، مسودات المحتوى، ومواصفات التصميم، وتقارير الـ QA).
3. **الملف الفعلي يكتب في موقعه الرسمي:** كود HTML النهائي للمحاضرة يكتبه مهندس الواجهات (`secod-frontend`) مباشرة في مجلد المقرر المعتمد في جذر المشروع (مثل: `Cloud-Computing/Lecture-04.html`) وليس داخل هذا المجلد.
4. **التسمية المعيارية:** تُسمى مجلدات المقررات بنفس الاسم الإنجليزي للمقرر في الموقع، وتُسمى المحاضرات بنمط `Lecture-XX`.

---

## 📂 الهيكل التنظيمي للمحاضرات (Standard Directory Hierarchy)

لكل محاضرة جديدة يُنشئ المنسق هيكل المجلدات التالي:

```text
.agent-workspace/
└── <Course-Name>/                           # اسم مجلد المقرر (مثلاً: Cloud-Computing)
    └── Lecture-<Number>/                    # رقم المحاضرة (مثلاً: Lecture-04)
        │
        ├── 00-source/                       # المادة الخام المرجعية من الأستاذ الجامعي
        │   └── [lecture-slides.pdf/.pptx]
        │
        ├── 01-analysis/                     # تفكيك المعرفة وأهداف التعلم
        │   └── lecture-analysis.md          # (المسؤول: Academic Analyst)
        │
        ├── 02-research/                     # التوثيق والتحقق من المعايير ودراسات الحالة
        │   └── research-report.md           # (المسؤول: Academic Researcher)
        │
        ├── 03-content/                      # المرجع الأكاديمي التفصيلي المعمق
        │   └── lecture-content.md           # (المسؤول: Academic Writer)
        │
        ├── 04-instructional-design/         # هندسة التجربة التفاعلية وبنك الكويز
        │   └── instructional-design.md      # (المسؤول: Instructional Designer)
        │
        ├── 05-implementation/               # تقرير الربط وتوثيق التعديلات البرمجية
        │   └── implementation-report.md     # (المسؤول: SECOD Frontend)
        │
        ├── 06-qa/                           # تقرير التدقيق الثلاثي وقرار الاعتماد
        │   └── qa-report.md                 # (المسؤول: Academic QA)
        │
        └── orchestration-summary.md         # تقرير الإنجاز النهائي الصادر من Orchestrator
```

## 📋 تفصيل وظائف المجلدات الفرعية والوكيل المسؤول

| المجلد | الوكيل المسؤول | الوظيفة والمحتويات المتوقعة |
|:---|:---|:---|
| **`00-source/`** | `secod-orchestrator` | إيداع الملفات المرجعية الخام (شرائح العرض PDF / PPTX، الملخصات، التسجيلات النصية). |
| **`01-analysis/`** | `academic-analyst` | توليد `lecture-analysis.md`: تفكيك الشرائح، جرد المفاهيم، كشف الفجوات، وصياغة أهداف التعلم. |
| **`02-research/`** | `academic-researcher` | توليد `research-report.md`: التحقق المرجعي من معايير NIST/RFC/ISO، ودراسات الحالة الواقعية. |
| **`03-content/`** | `academic-writer` | توليد `lecture-content.md`: الشرح الأكاديمي الشامل وفق منظومة المحاور العشرة لـ SECOD. |
| **`04-instructional-design/`** | `instructional-designer` | توليد `instructional-design.md`: تخطيط المحطات التعليمية، مواصفات المحاكيات، و 10 أسئلة كويز. |
| **`05-implementation/`** | `secod-frontend` | توليد `implementation-report.md`: توثيق إنشاء صفحة المحاضرة في مجلد المقرر وتحديث بوابة المقررات. |
| **`06-qa/`** | `academic-qa` | توليد `qa-report.md`: نتائج الفحص الأكاديمي، البيداغوجي، والتقني، وقرار الاعتماد أو الإرجاع. |

## 🔒 إدارة الحجم وإصدارات Git

- المخرجات النصية (`.md`) يتم تضمينها في مستودع Git لتوثيق تاريخ التطور المعرفي لكل محاضرة.
- الملفات الثنائية الضخمة جداً في `00-source/` (مثل مقاطع الفيديو أو العروض الضخمة التي تتجاوز 50 ميجابايت) يُوصى بإضافتها لملف `.gitignore` للحفاظ على خفة وسرعة المستودع.
