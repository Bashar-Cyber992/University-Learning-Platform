# 🛡️ SECOD Platform Rules & Engineering Guidelines

هذا المستند هو المرجع الدستوري الملزم لجميع الوكلاء الذكيين (Agents) والمهندسين العاملين في تطوير وتحديث منصة **SECOD**. الالتزام بجميع القواعد المذكورة هنا إلزامي بنسبة 100% دون أي استثناء.

---

## 1. هوية SECOD واستقلاليتها الأكاديمية (SECOD Brand Identity & Independence)

- **اسم المنصة الرسمي:** **SECOD** (Cybersecurity & IT Learning Platform).
- **الشعار اللفظي المعتمد (Brand Tagline):**
  > **Understand. Learn. Apply.**
  > (افهم. تعلّم. طبّق.)
- **المؤسس والمطور (Founder & Developer):**
  - **بشار زبله (Bashar Zblh)** — مبادرة تعليمية تقنية فردية ومستقلة.
- **الجمهور المستهدف والمقررات:**
  - تهدف المنصة إلى مساعدة طلاب المستوى الثالث في تخصصات تقنية المعلومات والأمن السيبراني (وطلاب كلية المنار بشكل خاص) على استيعاب المقررات التخصصية وفهم آلياتها الهندسية والعملية بعمق.
- **تنويه الاستقلالية الأكاديمية الصارم (Institutional Independence Disclaimer):**
  - **SECOD منصة تعليمية مستقلة تماماً ومبادرة شخصية من تطوير بشار زبله.**
  - **المنصة لا تتبع كلية المنار ولا تمثلها رسمياً بأي شكل من الأشكال.**
  - **لا توجد بين المنصة والكلية أي علاقة إدارية أو شراكة رسمية أو رعاية أكاديمية.**
  - **يُمنع منعاً باتاً صياغة أي نص، شعار، أو إشعار يوحي بالتبعية الرسمية أو الشراكة المؤسسية.**
  - يجب تضمين تنويه الاستقلالية الأكاديمية المعتمد في تذييل جميع صفحات المنصة دون تعديل نصه.

### 🖋️ نظام الطباعة (Typography System)

- **الخط العربي الأساسي:** `IBM Plex Sans Arabic` (مع خط `Cairo` كبديل قياسي Fallback).
- **الخط الإنجليزي والأرقام:** `Inter` (مع خط `Roboto` كبديل قياسي Fallback).
- **خط الأكواد والطرفيات والبيانات البرمجية:** `JetBrains Mono` (مع `SFMono-Regular`, `Consolas` كبدائل).
- **التوجيه ثنائي الاتجاه (Bi-Directional Support):**
  - دعم كامل لاتجاه القراءة من اليمين إلى اليسار (`dir="rtl"`) لكافة النصوص والشروحات العربية.
  - ضبط اتجاه تلقائي من اليسار إلى اليمين (`dir="ltr"`) لأكواد البرمجة، المسارات التقنية، والمعادلات.

### 🌗 دعم الوضعين الليلي والنهاري (Theme System)

- تعتمد المنصة سمة `data-theme="dark"` و `data-theme="light"` المطبقة على عنصر `<html>`.
- يجب أن تدعم جميع الصفحات والمكونات والرسوم التفاعلية التبديل السلس بين الوضعين بالاعتماد حصراً على متغيرات CSS (`var(--...)`) دون ألوان صلبة (Hardcoded Colors).

## 3. المعمارية التقنية للمنصة (Technical Architecture)

- **الركائز الأساسية (Core Tech Stack):**
  - **HTML5 القياسي الدلالي (Semantic HTML5):** عناصر نظيفة ومقروءة لمحركات البحث وقارئات الشاشة.
  - **CSS3 الحديث والمنظم (Modern Modular CSS3):** Flexbox, Grid, CSS Variables.
  - **Vanilla JavaScript القياسي (ES6+ Pure JavaScript):** بدون أي تبعيات خارجية ثقيلة.
- **حظر الأطر الخارجية (Framework Ban):**
  - **يُمنع منعاً باتاً إدخال React, Vue, Angular, Svelte, Tailwind CSS, Bootstrap أو أي مكتبة JS/CSS جديدة دون موافقة صريحة ومكتوبة من المطور.**
  - كل تفاعل أو محاكاة يجب بناؤه باستخدام Vanilla JS النظيف والسريع.

## 4. بنية المجلدات والمشروع (Project Structure)

```text
SECOD-Platform/
├── .agents/                               # منظومة الوكلاء وقواعد المشروع وبروتوكول التسليم
│   ├── rules/                             # القواعد البرمجية الملزمة (secod-project-rules.md)
│   ├── agents/                            # الوكلاء المتخصصون السبعة
│   └── handoff-protocol.md                # بروتوكول تسليم المهام بين الوكلاء
├── .agent-workspace/                      # مساحة العمل الوسيطة للمحاضرات (مخرجات مرحلية فقط)
├── assets/                                # الأصول المركزية المشتركة
│   ├── brand/                             # الشعار الرسمي والأيقونات المعتمدة
│   ├── css/                               # ملفات الأنماط المركزية (variables, layout, components...)
│   └── js/                                # محركات الجافاسكريبت الموحدة (main, components, quiz...)
├── components/                            # مكونات العرض المشتركة (header.js, footer.js)
├── courses.html                           # بوابة المقررات ومحرك البحث
├── index.html                             # الصفحة الرئيسية
└── [Course-Name]/                         # مجلدات المقررات الدراسية المستقلة
    ├── index.html                         # فهرس المقرر
    └── Lecture-XX.html                    # صفحات المحاضرات
```

- ملفات CSS المشتركة تعيش حصراً داخل `assets/css/`.
- ملفات JavaScript المشتركة تعيش حصراً داخل `assets/js/`.
- المكونات المركزية تعيش حصراً داخل `components/`.
- المحاضرات تضاف حصراً داخل مجلد المقرر التابع لها.

## 5. القواعد الصارمة للتطوير والهندسة (Engineering & Development Rules)

1. **افحص قبل أن تعدل (Inspect Before Modification):** اقرأ الملفات ذات الصلة وافهم السياق كاملاً قبل إجراء أي تعديل.
2. **أعد استخدام المكونات القائمة (Component Reuse):** استخدم المكونات المركزية (`header.js`, `footer.js`) ونظام الأنماط المشترك (`main.css`, `components.css`, `lecture-widgets.css`).
3. **منع التكرار نهائياً (Zero Duplication):** تجنب كتابة أكواد CSS أو دالات JS مكررة تؤدي وظائف موجودة مسبقاً.
4. **عدم إنشاء Header أو Footer جديد:** يُمنع إنشاء شريط رأس أو تذييل خاص بأي محاضرة؛ المكونات المركزية هي المصدر الوحيد للحقيقة.
5. **حظر تعديل الملفات المشتركة دون مبرر قطعي:** تعديل ملفات `assets/` أو `components/` يتطلب إذناً وتأكيداً بعدم كسر الصفحات السابقة (Zero Regression).
6. **حظر حذف المحاضرات أو ملفات الموقع القائمة:** يُمنع حذف أو استبدال أو إعادة تسمية أي صفحة من محاضرات المقررات السابقة.
7. **حظر تعديل الشعار الرسمي أو أصول العلامة:** أصول الهوية في `assets/brand/` مقدسة ومحمية.
8. **دعم كامل للتجاوب (Responsive Design):** يجب أن تظهر كل صفحة بشكل مثالي على الشاشات من 320px إلى 1920px.
9. **ربط متكامل وليس مجرد إنشاء صفحة:** إضافة المحاضرة لا تكتمل بإنشاء ملف HTML فقط؛ بل تتطلب ربطها بفهرس المقرر وبوابة المقررات `courses.html` وشريط التنقل والتذييل.
10. **التحقق الأكاديمي الصارم (Academic Fact-Checking):** لا تنشر معلومة تقنية أو تعريفاً دون توثيقه بمعايير رسمية معتمدة (RFC, NIST, ISO). يمنع التخمين والهلوسة منعاً قاطعاً.
